01 · Overview

What is MIRA?

MIRA is a physical robotic assistant built on the Seeed XIAO ESP32-S3 Sense microcontroller — a dual-core Xtensa LX7 system with a built-in OV2640 camera and I2S microphone. The robot features an orange 3D-printed head, an SSD1306 OLED display showing animated "eyes," a pan-tilt servo assembly for face tracking, and a Python backend running a local large language model.

Designed from the ground up to serve blind and visually impaired (BVI) users, MIRA rejects the always-on microphone model of commercial assistants. Instead, every interaction is intentionally initiated through an explicit gesture, preserving user autonomy and privacy.

"Privacy is not secrecy — it is the capacity for self-determination over one's own information." — Alan Westin, Privacy and Freedom (1967)

Design Principles

🤚

Gesture-Gated Activation

Camera and microphone only activate on explicit user gesture. No wake words, no always-on capture.

🔒

Edge-First Privacy

All vision inference runs on-device. LLM runs locally via Gemma 4 2B — zero cloud telemetry by default.

👁️

Zero-Screen Interface

OLED status display only. Designed for users who cannot interact with touchscreens.

🎯

Predictable Behavior

Deterministic state machine: face detected → 2-second gate → gesture → action. No surprises.

03 · Architecture

System Design

MIRA is organized as two cooperating layers: an embedded firmware running on the ESP32-S3 under FreeRTOS, and a Python companion on a connected laptop that handles LLM inference, TTS, and audio processing. 

ESP32-S3 (XIAO Sense)                    Laptop
┌──────────────────────────┐             ┌────────────────────────────────┐
│  OV2640 camera           │  USB-JTAG   │  assistant.py  (headless)      │
│  240×240 RGB565          │ ─────────►  │    or                          │
│  Face + gesture detect   │  RAW_GRAY   │  serial_viewer.py  (GUI)       │
│  Servo pan-tilt tracking │  DETECT JSON│                                │
│  OLED "eyes" display     │ ◄────────── │  → Gemma 4 2B (local CPU)      │
│  I2S mic capture         │  CMD text   │  → Groq API (llama-4-scout)    │
│  HTTP web dashboard      │             │  → pyttsx3 TTS (optional)      │
└──────────────────────────┘             └────────────────────────────────┘

oled_taskCore 0Animated eye rendering, state display

Interaction State Machine

  • Idle Camera off. Waiting for user presence. Minimal power consumption. OLED shows sleeping eyes.
  • Face Detected Camera active, face locked in frame. 2-second gate starts. Servo begins pan-tilt tracking. OLED eyes track face position.
  • Gesture Gate Watching for gesture within the face bounding box. No action until explicit signal.
  • Open Palm Microphone activates for 3–5 s audio capture. Audio sent to LLM for Q&A response via TTS.
  • Point Frame snapshot captured. Sent to LLM with prompt "What is the object being pointed at?"
  • Closed Fist Stop current recording or action. Return to face-detected state.

04 · Features

Capabilities

On-Device Vision (ESP-DL)

All vision inference runs directly on the ESP32-S3's LX7 cores using Espressif's ESP-DL library with INT8-quantized models. Per-frame inference runs in 100–200 ms, enabling ~5–10 fps detection in real time.

Face detection (HumanFaceDetect) Gesture classification Template-based matching (IoU) Kalman-filtered servo tracking

Gesture Vocabulary

GestureAction
Open Palm 🤚Start voice recording → LLM Q&A with TTS response
Point ☝️Capture frame → ask LLM "what is the object being pointed at?"
Closed Fist ✊Stop recording or cancel current action

LLM Backend

The Python companion supports two backends, selectable at runtime:

⚡

Groq API

Uses llama-4-scout-17b. ~1–3 s end-to-end latency. Requires internet and API key.

🏠

Local Gemma 4 2B

Runs entirely offline on the laptop CPU. Fully private, zero data egress. Slower (~10–30 s).

Web Dashboard

The ESP32 serves a live dashboard at its IP on port 80 after Wi-Fi connects. Accessible from any browser on the local network.

Live JPEG camera stream (/stream) Detection state (/detect) Camera on/off controls Servo pan/tilt controls Gesture training UI Snapshot capture (/snapshot)

Gesture Training

MIRA learns your specific gesture shapes via a template IoU training workflow — no factory model, no recompilation. Add custom templates over HTTP or the UART console. 

POST /cmd?op=gesture_train_start
POST /cmd?op=gesture_label&value=open_palm
POST /cmd?op=mark          ← stores current frame as template
POST /cmd?op=gesture_train_stop

06 · Build & Flash

Quick Start

Requirements: ESP-IDF v5.x or v6.x (tested on Windows with PowerShell).

1. Clone & configure

git clone https://github.com/Shi6aSK/MIRA.git
cd MIRA

# Set your Wi-Fi credentials in main/vision_config.h before building
# Edit: #define WIFI_SSID "your_ssid"
#       #define WIFI_PASS "your_password"

2. Build & flash firmware

# Activate ESP-IDF environment (Windows PowerShell)
. $env:IDF_PATH/export.ps1

# Build
idf.py build

# Flash and monitor (replace COM3 with your port)
idf.py -p COM3 flash monitor

3. Run the Python companion

cd tools
pip install -r requirements.txt

# Headless assistant (recommended)
python assistant.py --host http://192.168.X.X

# GUI viewer
python serial_viewer.py

Console Commands (USB-JTAG)

CommandEffect
stream_onEnable raw-frame + detection stream
stream_offDisable stream
track_onEnable servo face-tracking
track_offDisable servo tracking
statusPrint current detection state
